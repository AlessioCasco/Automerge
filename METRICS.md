# Automerge Metrics Configuration Example

This example shows how to configure automerge to track AI token usage metrics with Prometheus.

## Configuration

Add the following to your `config.json`:

```json
{
    "access_token": "your_github_token",
    "filters": [
        "^\\[DEPENDENCIES\\] Update Terraform",
        "^\\[DEPENDABOT\\]",
        "^\\[Dependabot\\]"
    ],
    "github_user": "your_username",
    "owner": "your_org",
    "repos": [
        "terraform-vault",
        "terraform-aws"
    ],
    "enable_ai_confidence_score": true,
    "enable_ai_automerge_action": false,
    "ai_provider": "github",
    "ai_config": {
        "github": {
            "api_base": "http://localhost:4141",
            "model": "claude-sonnet-4"
        },
        "claude-code": {
            "api_base": "https://api.anthropic.com",
            "api_key": "your_anthropic_api_key",
            "model": "claude-sonnet-4"
        }
    },
    "minimum_confidence_score": 80,
    "auto_merge_environments": ["development", "sandbox"],
    "metrics_pushgateway_url": "http://prometheus-stack-prometheus-pushgateway.monitoring.svc.cluster.local:9091"
}
```

## Metrics Generated

The system will generate two Prometheus metrics:

### `automerge_input_tokens`
- **Description**: Number of input tokens used by AI analysis
- **Labels**:
  - `repo`: Repository name (e.g., "terraform-vault")
  - `model`: AI model name (e.g., "claude-sonnet-4")
  - `engine`: AI engine (e.g., "claude-code", "github-copilot")

### `automerge_output_tokens`
- **Description**: Number of output tokens generated by AI analysis
- **Labels**:
  - `repo`: Repository name (e.g., "terraform-vault")
  - `model`: AI model name (e.g., "claude-sonnet-4")
  - `engine`: AI engine (e.g., "claude-code", "github-copilot")

## Example Metrics

```
# HELP automerge_input_tokens Number of input tokens used by AI analysis
# TYPE automerge_input_tokens gauge
automerge_input_tokens{repo="terraform-vault",model="claude-sonnet-4",engine="claude-code"} 150

# HELP automerge_output_tokens Number of output tokens generated by AI analysis
# TYPE automerge_output_tokens gauge
automerge_output_tokens{repo="terraform-vault",model="claude-sonnet-4",engine="claude-code"} 75
```

## Prometheus Queries

### Total input tokens across all repositories:
```promql
sum(automerge_input_tokens)
```

### Input tokens by repository:
```promql
sum by (repo) (automerge_input_tokens)
```

### Input tokens by AI engine:
```promql
sum by (engine) (automerge_input_tokens)
```

### Cost estimation (assuming $0.01 per 1K tokens):
```promql
sum(automerge_input_tokens + automerge_output_tokens) * 0.01 / 1000
```

## Configuration Options

### `metrics_pushgateway_url`
- **Type**: String or null
- **Default**: null (metrics disabled)
- **Description**: URL of the Prometheus Pushgateway to send metrics to
- **Examples**:
  - `"http://pushgateway:9091"`
  - `"https://prometheus-pushgateway.example.com:9091"`
  - `null` (to disable metrics)

### Validation Rules
- Must be a valid URL starting with `http://` or `https://`
- Must include a hostname (not just protocol)
- Empty string is allowed (disables metrics)
- `null` is allowed (disables metrics)

## Usage

1. **Enable metrics**: Set `metrics_pushgateway_url` in your config
2. **Run automerge**: The system will automatically track token usage
3. **View metrics**: Check your Prometheus dashboard for the metrics
4. **Monitor costs**: Use the metrics to track AI usage and costs

## Troubleshooting

### Metrics not appearing
- Check that `metrics_pushgateway_url` is correctly configured
- Verify the Pushgateway is accessible from the automerge instance
- Check automerge logs for metrics-related errors

### Invalid configuration
- Ensure the URL starts with `http://` or `https://`
- Make sure the URL includes a hostname
- Check that the URL is accessible

### High token usage
- Monitor the metrics to identify repositories with high usage
- Consider adjusting AI analysis frequency
- Review confidence score thresholds
